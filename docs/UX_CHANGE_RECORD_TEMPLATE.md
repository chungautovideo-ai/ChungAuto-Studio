# Mẫu ghi phân tích cho thay đổi UX/UI

Dùng trước khi thiết kế/code; điền trong tài liệu hạng mục, không tạo một trang điều hướng mới trong sản phẩm. Với thay đổi nhỏ, ghi gọn từng dòng; với luồng lớn, thêm wireframe/prototype.

- **Ngày / hạng mục / mục inventory:**
- **Công việc người dùng / kết quả mong muốn / thiết bị:**
- **Hiện trạng đã quan sát:** màn/ảnh/code, điểm vào, bước thao tác và vấn đề; nguồn bằng chứng cụ thể.
- **Tham khảo:** VEK/CapCut/Premiere/AIEV/Studio hoặc ứng dụng phù hợp; bằng chứng đã xem, điểm học và giới hạn. Nếu dùng lại khảo sát trước, dẫn đúng tài liệu.
- **Bản đồ tích hợp:** chức năng → màn/tab → component/service/file; vì sao dùng lại hoặc cần thêm.
- **Luồng đích / bố cục:** hành động chính, nhóm thường dùng, phần nâng cao, cách quay lại.
- **Trạng thái:** loading/empty/error/retry/unavailable/dirty/conflict; điều gì chỉ preview.
- **Thiết kế chung:** token/icon/control dùng lại; khác biệt có lý do.
- **Responsive / keyboard / focus:** breakpoint và hành vi từng vùng.
- **Dữ liệu / tác động:** Save/Undo/reopen, revision/AI job/preview/final; thao tác nào thực thi tốn phí hoặc phát hành.
- **Nghiệm thu dự kiến:** luồng và bằng chứng cần có, phạm vi chưa kiểm.
- **Sau triển khai:** file đã đổi, bằng chứng thực, kết quả và giới hạn; cập nhật BUILD_STATUS/đặc tả liên quan.

Ví dụ tham chiếu đã có: nhóm Âm thanh dùng submenu Bộ lọc và cách duyệt nhạc từ ảnh CapCut; đọc AUTO_EDIT_UX_AUDIO_PRESETS_AUDIT_2026-11-04.md và AUDIO_SPACE_INTEGRATION_BROWSER_SMOKE.json. Ví dụ này không thay phân tích cho tính năng khác.
